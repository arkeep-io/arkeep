# 0016. Publish the agent to the AUR with GoReleaser

- **Status:** Proposed
- **Date:** 2026-11-04
- **Deciders:** @TheGuit, Arkeep maintainers

## Context

Arch Linux users install the agent by hand (binary, systemd unit, environment
file) or maintain a private PKGBUILD that they rebuild at every release. The
Arch User Repository (AUR) is where Arch users expect third-party software:
an AUR helper (`yay`, `paru`) installs it and upgrades it with the rest of the
system.

An AUR package is a Git repository on `aur.archlinux.org` holding a
`PKGBUILD` and its `.SRCINFO`, pushed over SSH with a key registered on an AUR
account. A package that repackages a prebuilt binary must be named with a
`-bin` suffix.

Releases are built by GoReleaser
([0011](0011-go-monorepo-conventional-commits-goreleaser.md)), which already
produces the agent archives for Linux and has a native AUR publisher
(`aurs`).

## Decision

- Every stable release publishes the agent to the AUR as
  **`arkeep-agent-bin`**, through the `aurs` entry of `.goreleaser.yml`. No
  server package is published.
- The PKGBUILD is generated by GoReleaser from the agent archives already
  attached to the release, with their SHA-256 from the same build: it
  downloads nothing else. It declares every architecture pacman knows among
  those archives (x86_64, aarch64, armv7h).
- The package installs the binary to `/usr/bin`, the unit from
  `deploy/systemd/arkeep-agent.service` and an `/etc/arkeep/agent.env`
  template (mode 600, declared in `backup=`). **The unit is used as is**, apart
  from the binary path: a change the package needs goes into the upstream
  unit, so every installation runs the same service definition.
- Publishing needs the `AUR_SSH_PRIVATE_KEY` repository secret, the private
  half of a dedicated key registered on the maintainers' AUR account. Without
  it, GoReleaser still renders the PKGBUILD in `dist/` and skips the push, so a
  release never fails because of the AUR. Pre-releases are never pushed
  (`skip_upload: auto`): pacman rejects `-` in `pkgver`, and AUR users expect
  stable versions.
- The release notes show the AUR install command only when the package is
  published.

## Consequences

- Arch users install with `yay -S arkeep-agent-bin` and get updates with their
  system upgrades, without a manual step from the maintainers.
- The AUR package is tied to an AUR account owned by the maintainers. Losing
  the key or the account blocks updates until a new key is registered.
- The package follows the upstream systemd unit: changing it changes the
  behavior of Arch installations at the next release.
- A failed push leaves the release complete but the AUR one version behind.
  The PKGBUILD in `dist/` can be pushed again by hand.

## Alternatives considered

- **A hand-written PKGBUILD and a dedicated workflow job** — full control over
  the PKGBUILD, but more CI code to maintain than GoReleaser's native support.
- **A third-party action** (e.g. `KSXGitHub/github-actions-deploy-aur`) —
  hands the AUR SSH key to external code.
- **A source package** (`aur_sources`, building with Go on the user's machine)
  — slower installs and a Go toolchain on every machine, for the same
  binaries.
- **Packaging-specific systemd drop-ins** — every package would diverge from
  the documented unit.
